# Windows synthetic peer timeout

The synthetic invalid-result peer originally timed out with `configuration_owner_unavailable` instead of `configuration_response_invalid`; actual owner/lease/catalog cases passed. Reader ordering, awaiting EOF, stdout callbacks and direct file-descriptor writes did not fix it. The production reader observed only the 49-byte readiness frame. Independent Node and Bun parents both received the complete matching response before EOF.

The controlled fix in local `05704d5`, public `c398d9b2`, awaits the request outcome before invoking Bun assertions through the existing `expectError` helper. It preserves assertions that failure is an Error with the exact expected code; successful resolution fails the assertion. Windows run [39814441194](https://github.com/CodyBontecou/Thumble/actions/runs/39814441194), job `119949129091`, passes the focused case in 43.07 ms. This isolates an asynchronous rejection-matcher interaction with pipe IO in Bun 1.4.3 Windows; it does not prove an upstream engine implementation cause. The repository already used this helper for a separate Windows socket rejection failure.

Cleanup local `5e3761f`, public `d8e42c895807be1865a6f8e55729d2107dd08001`, removes all temporary peer/reader counters, traces, direct-fd experiments and the independent-reader script. The peer again uses normal `process.stdout.write`. Production transport matches the approved owner snapshot, with unchanged two-second request and three-second startup deadlines. The useful focused Windows workflow remains. The exact cleaned source passes Windows run [39816744676](https://github.com/CodyBontecou/Thumble/actions/runs/39816744676), job `119957746813`. The isolated projection passes 155 source tests / 2,927 assertions and standalone packaging / 64 assertions.

Full host run [39816736449](https://github.com/CodyBontecou/Thumble/actions/runs/39816736449) passes macOS/Linux but fails a different Windows native stale-grant case before the TypeScript suite: the current session is neutral with `input_expired` after another peer's stale grant is rejected. This does not invalidate the focused pipe fix and is not a green full-Windows acceptance result. No test skip or input deadline relaxation was introduced.

## Separate Windows native timing failure

In terminal Windows job `119957071054`, phases are current-held acknowledged at 2,318 ms, sampling-first-native-ack at 2,508 ms, stale authenticated at 2,716 ms, and stale rejected at 3,383 ms. The status immediately afterward reports generation 1 inactive, neutral and `input_expired`. The sampling thread then fails its ordered control receive because the channel is closed. The earlier durable clock probe in the same job measures WAL commit median 18,893 us, p95 101,713 us and maximum 311,366 us; these measurements motivate IO investigation but do not alone prove the timeout cause.

Ranked falsifiable hypotheses: (1) durable trust checks hold the shared mutation fence across storage latency, preventing active input from reaching the receiver; (2) the fixture's input plus durable status acknowledgment round trip creates TTL-sized producer gaps; (3) hosted scheduling pauses the producer despite a nonblocked authorization path. The observed failure command is `cargo test --locked --manifest-path native/receiver/Cargo.toml --test native_ingress_process stale_grant_receipts_and_old_generation_packets_cannot_replace_or_release_new_configuration -- --exact --nocapture`. The current fixture already sends continuous input on a separate thread and bounds one ordered round trip; no skip, unchecked producer queue or larger input TTL is an acceptable substitute for distinguishing those causes.
