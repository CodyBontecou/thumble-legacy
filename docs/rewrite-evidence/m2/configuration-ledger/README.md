# Durable configuration ledger/service seam

The portable application port and Bun SQLite adapter commit raw lossless source and immutable receipts atomically. The service now owns the DB lease, closes it before endpoint disappearance, and starts/stops the same compiled backend without a checkout or Bun on PATH. Runtime publication remains ephemeral; typed document validation, caller capabilities, assets, CLI/MCP writes and launch gates remain pending. No retained desktop authority or real user data was opened/migrated.

Final checks: 90 host/portable tests, 80 Rust unit + 12 actual-process tests, Clippy all targets, standalone package 1 test/41 assertions, formatter/types/generated/boundary/actionlint. Built-in Bun SQLite reports 3.51.0 locally. New workspace metadata only: no registry dependency versions added/changed. The native helper adds only fixed configuration main/journal protection using existing Unix/Windows policy. Main/journal links, orphan auxiliaries and unsupported WAL/SHM are refused before SQLite admission.

Nine storage tests include separate-process exclusive writer ownership and abrupt death, raw full-width source durability, receipt replay after later writes, changed-payload rejection, CAS/no ID reservation, revisions above safe integers and uint64 exhaustion, real SQLITE_FULL rollback after source update, foreign/anonymous/forged schema refusal, source hash corruption, native-private modes, and unsafe links/extra native arguments. A service process test requires the DB lock released at endpoint disappearance and proves generic fixture source survives restart without activating native input.

Review found two concrete gaps before publication: version/name checks alone accepted a forged non-STRICT database, and sparse identifier arrays could serialize unreadable receipts. Both red reproductions are retained privately. Final code verifies exact STRICT DDL, quick-check, source/head consistency and dense own data entries without executing index getters. It never repairs or overwrites an unknown schema. All final tests pass. Generic source acceptance is not profile validity: trusted application use cases must derive payload fingerprints and validate documents/capabilities before calling the port.
