# M3 bounded native phone delivery

The Android input engine can now publish sealed packets directly into `NativeTLSDelivery` without waiting for socket I/O. A writer worker and a separate reader worker share one pinned TLS connection, with only one concurrent operation per direction. The worker retains one replaceable latest input snapshot, eight outbound control frames and eight inbound control frames. Overflow, wrong-direction input, connection failure and explicit close retire the connection and discard pending frames. No callbacks or packet queues cross React.

Close transitions state immediately and wakes the writer before scheduling at most one transient native closer. The input thread never waits for TLS shutdown; a test holds platform shutdown behind a latch and verifies that close returns and subsequent offers fail. The socket adapter aborts raw TCP before TLS cleanup so stalled TLS operations cannot hold the deadline watchdog. Late connection completion after close is rejected. A fresh connection and grant remain necessary after retirement.

Headless verification passes **40 Android JUnit tests with zero failures/skips**, Android AAR/lint and **20 Swift tests**. Deterministic blocked-write tests prove immutable packet ownership and coalescing to the newest snapshot. Other cases cover bounded control/inbound queues, wrong directions, connection failure, malformed packet sizes and close-during-connect. An initial test polling helper consumed a queued response twice and was corrected to evaluate destructive predicates only once.

Actual TLS integration now runs native touch engines through their encryption channels to the Rust recording receiver. Android sends neutral/held state while its reader is blocked waiting for control and becomes neutral on transport closure. The iOS path verifies five simultaneous touches: both sticks, both held triggers and a face button, followed by transport-loss neutralization and rejection of same-generation reconnect. These synthetic loopback tests do not emit OS input or establish physical timing/gameplay acceptance. The existing direct iOS SDK compilation remains valid for unchanged production Swift source; only its integration test changed in this slice.
