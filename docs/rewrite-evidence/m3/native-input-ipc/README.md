# Local native input IPC checkpoint

The actual recording receiver now owns capability-authenticated loopback IPC for configuration metadata, fresh exact-generation grants, sealed packets and scoped release. Native socket workers never apply output; the independent safety loop drains bounded queued operations. The native client verifies a fresh HMAC server proof before sending the private capability, protecting stale endpoint port reuse. Keys are native-only opaque values and never enter the unchanged Bun stdio schema.

Local verification passes 77 unit tests and four actual receiver-process tests (81 Rust total), all-target Clippy, 74 TypeScript tests/916 assertions and standalone packaging (one test/53 assertions). Process coverage routes native encrypted held state, rejects replay without renewing TTL, fences recorded samples, preserves owner renewal, handles replacement/stale cleanup, neutralizes current disconnect, expires a lost owner despite continuous native packets and expires input while IPC sockets stall. Unit coverage includes private ownership/rotation, corrupt/symlink endpoints, malformed frames/capabilities, stale-port server impersonation, expired queue work, abandoned grant delivery and bounded draining.

All new checks are local macOS evidence. This source has not been published or verified on Windows; hosted results for the earlier approved phone snapshot do not prove this implementation. Authenticated phone control still reports input unavailable until its native broker and phone grant/engine binding are connected. UDP and actual OS output/signing/gameplay acceptance remain pending. No retained desktop functionality is removed; the full rewrite goal remains active.
