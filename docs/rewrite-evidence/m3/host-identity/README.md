# M3 native persistent host identity

Explicit `identity initialize` and `identity show` CLI commands now provision/inspect the native host certificate without starting a service, opening a desktop GUI or exposing private key bytes to JavaScript. An explicit persistent directory keeps this identity separate from disposable runtime state. [ADR 0004](../../../adr/0004-rewrite-persistent-host-identity.md) specifies ownership, private binary format and recovery behavior.

The native helper uses private filesystem permissions/Windows owner+SYSTEM ACLs and an exclusive identity lock. It writes and flushes staged material, atomically publishes without clobbering another record, and recovers verified interrupted creation with the same key/pin. Partial, corrupt, conflicting, expired or policy-invalid records fail without silent replacement. Read-only inspection does not initialize/recover key material. Network/input remain disabled; identity readiness alone grants no phone trust.

Local checks pass **33 Rust tests**, Clippy with warnings denied, **67 TypeScript tests** and the separate standalone package test (**29 assertions**). Cross-process CLI tests verify a stable pin matching certificate DER, unchanged persisted material and public-only output. Standalone setup/inspection works outside the checkout with Bun removed from PATH. Tests exercise both interruption boundaries, ownership/namespace conflicts, malformed/oversized/trailing records, key mismatch, name/date/server-usage policy and Unix alias refusal. Windows-specific storage behavior still needs hosted tests for this new source.
