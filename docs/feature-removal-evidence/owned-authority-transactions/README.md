# Durable owned-authority transactions

`owned_migration` now prepares and persists a complete owned receiver state under the matching `AuthorityLock`. Persistent schema 3 continues to require profile format 4. Explicit persistent schema 4 requires profile format 5, including one landscape layout and complete owned appearance/resources. Fresh installations remain schema 3. Legacy configuration installs cannot overwrite an owned authority; old wire customization/portrait-preference mutations return an error without mutation, and owned snapshots omit skin/portrait capabilities.

The candidate begins with exact validated private receiver bytes. Only credential-free profile data enters native preparation. The raw source's identity, trust metadata, binding maps, profile selection, commit/adoption history and unknown numbers/fields survive the four scoped state changes. Original package archives must match the native preparation's hashes and are retained for rollback; the bounds are 40 MiB per archive and the existing library's 512 MiB aggregate ceiling.

The backend syncs the exact original state, package backups, staged owned destination and prepared receipt in private directories/files. The shared atomic state installer rereads the exact source before rename. Commit acknowledgement follows successful installation. Explicit recovery verifies source/destination/package digests, schema and revision relationships before finishing recorded intent. A matching existing backup is synced again during retry; recovery syncs an observed state rename before acknowledging it. Staging files without a valid receipt never establish completion. Corruption, unexpected source bytes, wrong leases and unsafe paths fail closed.

Rollback preserves the original backup, requires the committed receiver state to remain unchanged, and restores original profiles/resources while advancing the revision again. A caller must durably/idempotently restore and verify each legacy package before the old state is published. Restore failure leaves owned state intact and a recoverable rollback intent. The tests use a real private restoration store; the production legacy-library adapter remains to be wired. An unrelated pairing/profile update after commit prevents rollback from overwriting it.

Ten transaction tests consume all five actual converted profile fixtures. They exercise real filesystem commit/restart/replay/rollback, source conflicts, incomplete/corrupt backups, all commit checkpoints, rollback acknowledgement interruption, resource restore failure/retry, credential-free receipts, original metadata/numeric preservation, actual owned HostCore startup and old-phone rejection, and nonmutating legacy wire guards. The full Rust gate passes 545 tests (three existing native-dependent ignored); the required Apple gate passes 40 constrained-stack tests and both Debug builds. Exact tested source/log hashes are in verification.json; filtered Rust and native stack logs accompany it.

Activation remains incomplete: normal startup/CLI/MCP do not dispatch migration or recovery, shipping phones still offer format 4, and no existing user account has been migrated. Runtime publication, production resource restoration, owned CLI/MCP edit transactions, actual format-5 phone transfer and pending-edit reconciliation/bounds remain required. Physical haptics, input latency and live WoW were not exercised. The Apple gate uses the previously recorded isolated Apple source overlay; no Apple source changes are part of this batch. The Rust gate uses the shared working tree and includes concurrent unrelated changes.
