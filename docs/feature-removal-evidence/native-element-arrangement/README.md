# Native element creation and arrangement

Native `element add`, `duplicate`/`copy`, `align` and `distribute` now use typed live/offline authority transactions. Together with the preceding set/nudge/delete/reset work, these handlers no longer call legacy profile persistence. Creation accepts all six existing kinds and the bounded non-file changes object, with an optional explicit UUID. Otherwise creation and duplication derive control IDs from the invocation UUID, so retries cannot create additional controls. Selectors must resolve to distinct canonical controls. Arrangement uses the saved profile canvas and the existing native algorithms.

Identity reconciliation now retains every existing paint snapshot and canonical control. Added controls receive their declared paint; duplicated controls inherit their source paint independently in each of the eight saved states. Resolved Light/Base paint is never copied into canonical geometry/input storage. The host validates exact per-state source cloning for duplication, alongside the unchanged executable ownership and geometry checks. Native and Rust regressions reject forged clone paint and unrelated geometry. The existing six native response oracles remain exact.

Two new planner tests cover deterministic/explicit IDs, selection counts, duplicate selection and conflicting creation kinds. Two new Swift Testing cases cover command encoding and eight-state duplication after reset/hide. Two host tests independently accept the frozen native duplicate and reject tampered results. The native sequence fixture includes deterministic correlated request/response packets, checked by the normal fixture verifier.

The temporary-account process flow covers explicit and generated creation IDs, retry without extra controls, duplication with preserved state paint, center alignment, distribution, duplicate-selector refusal and cleanup that restores original canonical controls/paint. It also retains the previous CLI/MCP edits, haptics, restart replay, online/offline profile routing and raw design capture checks. This does not establish physical haptics, input latency, live game acceptance or phone-edit reconciliation.

Verification excludes concurrent shared-workspace changes. The tested main CLI overlay is committed independently, leaving concurrent working-tree CLI edits present. Portable owned interchange, file-backed artwork workflows, phone activation, migration and runtime/UI retirement remain outstanding.
