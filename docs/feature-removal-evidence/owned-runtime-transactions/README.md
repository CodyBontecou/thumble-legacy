# Live owned configuration transactions

The receiver routes its existing configuration transactions to the raw owned draft store when its authority uses schema 4. Begin/get/edit/rebase/validate/preview/save/discard retain their existing control protocol and MCP tools. A new `thumble-host configuration` command group exposes that same local transaction path directly, returning control-response JSON and nonzero failure status. No desktop application is started.

Draft reads, schema validation and native design operations execute outside the input mutex; only the disk/live-state comparison requires the mutex during reads. Save holds the synchronization barrier, validates the exact source and candidate, requires successful held-input release before persistence, atomically installs raw state, activates the already validated state and records durable replay before best-effort draft cleanup. Unknown state/trust metadata and numeric tokens survive. A non-regular authority file is opened nonblocking and rejected, preventing a FIFO from waiting for a writer while configuration is requested.

Seven new unit cases cover the routed transaction lifecycle, preview/validation, replay, write-disabled saves, disk/memory divergence, rebase/discard, release failure and retry, nonblocking rejection of a FIFO authority, required CLI revisions/operation sources, and ambiguous/oversized operation input. The native bridge remains the operation validator for retained design operations; structural draft validation does not claim a native render.

The real process verifier installs the isolated host/MCP binaries beside the previously verified native helper in a temporary directory, seeds an explicit schema-4 authority, and runs native geometry edits through CLI plus native haptic edits through stdio MCP. It checks both commit retries, all eight paint states, retained resources, an exact unknown integer, receiver restart and durable replay of the earlier commit after a later configuration revision. Input output is disabled and no desktop GUI is installed in the temporary bundle. This proves local process integration, not physical haptics, game input, pixel rendering or latency acceptance.

The Rust gate runs against committed HEAD plus only this batch's modules, dispatcher changes and nonblocking state-read flag. Concurrent WoW dispatcher/CLI/MCP changes remain outside the commit. Apple verification uses the unchanged native isolated baseline. Logs, tested source hashes and binary hashes are recorded in `verification.json`.

Owned transaction dispatch is conditional on an already owned authority. Fresh state and shipping phone offers remain legacy; this batch does not activate user migration, owned phone synchronization, automatic recovery or runtime skin deletion. The high-level legacy `thumble profile` planning/import path, complete retained operation acceptance and phone reconciliation remain required before migration activation. Structural preview uses the canonical landscape `primary` variant.

Final verification passes the isolated Rust gate (563 tests, three existing native-dependent ignored), formatting/Clippy/target checks, 41 constrained-stack tests and both Apple Debug builds, plus the real headless CLI/MCP/native-helper restart flow. The held-input regression includes an output-side hold without core ownership; both are released before persistence.
