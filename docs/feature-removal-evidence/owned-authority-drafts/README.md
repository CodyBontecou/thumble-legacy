# Durable owned configuration drafts

Owned drafts retain validated raw v5 documents rather than serializing typed projections. The private, separately versioned store provides operation replay, revision checks, expiry, atomic writes, three-way rebase, and source-bound commit preparation. Standalone commits require the existing exclusive authority lease, compare the exact live state before installation, preserve current trust and unknown state metadata, and record replay receipts before draft cleanup. Native design operations use the previously verified owned bridge; profile rename is handled directly.

Rebase merges identified elements and known customization maps, retains raw numeric tokens, and rejects conflicting values, incompatible ordering and delete/edit collisions. Only known profile update timestamps receive a maximum merge. Anonymous arrays changed by both sides require conflict resolution. File permissions, ownership, no-follow reads, size/operation limits and the configuration credential boundary remain enforced.

Ten new tests cover restart precision, replay without provider execution, operation conflicts, concurrent revision writers, no-ops, expiration, invalid provider outcomes, unsafe files, metadata/trust preservation, commit replay after draft removal, successful and conflicting rebases, identity ordering, delete/edit collisions and paired customization maps. They use the frozen owned-configuration fixture. These are backend tests; they do not prove receiver routing, CLI/MCP command acceptance, phone editing or physical-device behavior.

The shared-checkout Rust gate encountered two MCP tool-count failures in concurrent WoW changes (29 tools versus the old expectation of 28). The isolated Rust gate uses committed HEAD plus only the two new modules and their module declarations. Shared changes are neither reverted nor included in this batch. Apple stack verification uses the existing isolated checkout: 178 tracked source/test/project/script files match committed HEAD exactly; two unrelated process verifier scripts are absent. The complete compared source hashes and logs accompany the receipt.

This batch does not enable owned authority transaction dispatch, automatic migration, shipping phone format negotiation, or runtime package deletion. Existing profiles and deployed services are unchanged. The next integration step is routing the existing configuration transaction control requests through this store when the authority uses the owned schema, then proving the same path through CLI/MCP and retained peers.

Verification: the isolated Rust gate passes formatting, Clippy, workspace tests (556 passed, 3 existing ignored) and target checks. Apple verification passes 41 constrained-stack tests and both Debug builds. See `verification.json` for scope and hashes.
