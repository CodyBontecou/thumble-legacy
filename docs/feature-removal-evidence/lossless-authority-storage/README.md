# Lossless receiver state persistence

Production `storage::save_atomic` now reads the exact private current file, makes before/after views with the same state codec, and merges only typed changes into original bytes. Unknown root/profile/trust metadata, numeric literals and document framing survive retained owners. An unchanged save keeps exact bytes. The explicit legacy active/default selection aliases retain their spelling during edits, preventing duplicate semantic fields. The merged result must decode to the exact requested typed state before it can be installed.

Complete state input, projections and output stay within the existing 16 MiB loader ceiling. The private temporary file is synced before installation; an exact reread must still match the source, then atomic rename and parent sync complete the save. A failure before rename removes the temporary file and leaves the authoritative source intact. Callers must still hold the existing authority lock/mutex: the reread is additional conflict detection, not a replacement for writer exclusion or a filesystem CAS primitive. Removal of an owner containing unprojected opaque data fails closed instead of guessing its deletion policy.

Eight new tests cover real state files, no-op identity, profile/pairing changes, initial-install/source replacement races, simulated interruption before rename, ambiguous input without token exposure, symlinks, both legacy selection alias pairs, and exact/oversized raw bounds. A standalone CLI rename holds the actual AuthorityLock and runs the production draft/CAS/persistence path; replay keeps the same bytes, revision, identity and trust metadata. The full Rust gate passes 535 tests with three existing native-dependent ignored tests. The repeated isolated Apple gate passes 40 constrained-stack tests and both Debug builds with unchanged budgets. Filtered logs and source/original-log hashes are recorded alongside this file.

This is active version-4 storage hardening required by the migration, not format-5 activation. Durable migration backups/receipts, transaction recovery/rollback, owned authority integration and phone/pending-edit delivery remain outstanding. No physical haptic, latency or live WoW acceptance is claimed.
