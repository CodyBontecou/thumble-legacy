# Native CLI element transactions

Native `element set`, `nudge`/`move`, `delete`/`rm` and `reset` now issue typed high-level authority commands. They no longer load or persist the legacy store. The host resolves canonical UUIDs, labels and preset aliases, rejects ambiguous or missing controls, validates changes and uses the existing revision/operation/commit path. Nudge retains point-based units and the saved profile canvas. Preset deletion hides the preset; custom deletion removes its identity and paint entries.

Set provides geometry, label/kind, visibility, lock and haptic convenience flags. Bounded changes JSON exposes the existing typed non-file appearance/behavior/output schema. Unknown fields, duplicate JSON keys, repeated flags and conflicting edits fail before persistence. Existing safe descriptor-based file reading is reused; file-backed artwork import and the remaining create/duplicate/align/distribute commands still require their authority cutover. The CLI help and persistence allowlist reflect the actual supported surface.

Chained native acceptance uncovered a separate correctness bug: removing a custom control after preset reset/hide resolved every paint state and baked the Light/Base display result back into canonical input/layout storage. That introduced an unrelated visual-style field and was correctly refused by the host's ownership and render guards. Removal now filters the control IDs in the existing immutable appearance snapshots and leaves canonical controls untouched. Addition retains its established behavior. No host input or paint guard is loosened, and existing six native response fixtures remain exact.

Two new Rust planner tests cover canonical selection, duplicate/unknown changes refusal and identity retention across set/nudge/delete/reset. Two Swift Testing cases check command encoding and point units; a third native regression uses the frozen post-reset/hide fixture and compares every surviving canonical control after custom deletion. The fixture manifest is verified by the normal removal-fixture gate.

The real temporary-account process flow covers native CLI set plus haptics, exact retry, malformed-input refusal, offline nudge/reset, preset hide and custom removal across eight appearance states. It also retains the prior CLI geometry, stdio MCP haptic, online/offline profile, receiver restart and exact raw design-capture checks. Physical haptics, game input, latency and phone editing are not inferred from these process/model checks.

Verification uses isolated source overlays and excludes concurrent WoW and other shared-workspace edits. The main CLI file is committed from that tested overlay while its concurrent working-tree edits remain present. Source, fixture, binary and log hashes are recorded in `verification.json`. Automatic migration, owned portable interchange, phone activation, remaining design-command cutover and desktop retirement remain unfinished.

Final verification passes the isolated Rust gate (569 tests, 3 existing native-dependent ignored), 41 constrained-stack tests and both Apple builds, seven existing native owned tests plus three Swift Testing cases, rebuilt native CLI/helper binaries, six exact native packet oracles, the fixture verifier and the complete temporary-account process flow. The final process flow also checks the percentage/millisecond haptic convenience parsers.
