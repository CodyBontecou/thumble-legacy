# Owned projection merge

The protocol now has a bounded in-memory merge from two typed views into original JSON. It preserves opaque values, unchanged numeric spellings, escaped keys, and outer document whitespace. Object arrays preserve metadata by identity. Unknown-container removal/type changes, opaque unidentified arrays, new fields colliding with non-null unknown values, and UUID map-key aliases reject without changing source. The twelve protocol cases include UUID case handling, duplicate/NFC keys, resource-independent byte bounds, exact no-op framing, and a cold merge through 24 extra object levels on a 512 KiB thread.

`OwnedConfigurationDocument::with_projected_changes` accepts validated v5 projections and revalidates the complete merged result. The real native projections in `Host/fixtures/owned-projection-merge/v1` deliberately omit opaque root/profile metadata. Rust applies their seven-edit changes to the original specimen, retaining beyond-u64 integers/precise decimals and comparing all eight appearance resolutions with the prior writer destination. Apple reads the merged document and compares complete native profiles; Android independently checks geometry, icon and double-tap haptics in all eight states. Resource bytes remain part of the shared owned fixture. This is codec/appearance evidence, not a pixel comparison or device haptic test.

The final full Rust gate passes 517 tests; three existing native-dependent cases remain ignored and are not counted as passing. Native focused verification passes five tests; the required stack script passes 39 cases, both builds and unchanged static budgets. Android passes 205 unit cases and device-test assembly in an isolated committed-base snapshot. Source comparison against base `64871cb` (normalizing the archive’s configured Windows-wrapper CRLF) finds only the two recorded test-file overlays in the native/Android source trees; tested fixture bytes match the frozen files. Concurrent unrelated checkout changes were excluded. Exact sources and log hashes are in `verification.json`.

The authority must still bind projection provenance to the exact source/revision, use the same codec for both views, handle schema-specific aliases and resource pruning, and commit with backup/CAS/receipt/recovery. A typed projection is not an authoritative replacement document. This does not assemble legacy v4 data into v5, reconcile pending phone edits, admit live transfers, activate format 5, or remove the remaining skin/portrait/desktop runtime. Those remain part of the active goal.
