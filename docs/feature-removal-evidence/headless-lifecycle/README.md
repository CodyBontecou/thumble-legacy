# Headless receiver lifecycle

The native CLI now delegates `server start|stop|restart` to its validated sibling `thumble-host`, with bounded process I/O, timeout, and a HOME-only environment. It accepts only the receiver's curated start flags and rejects malformed ports, duplicates, unknown arguments, and flags on stop/restart. It no longer opens the desktop app or posts GUI lifecycle commands. Existing host startup retains its authority lock and supported legacy-defaults import; version-5 migration is still gated.

Status and pairing inspection now use a headless-only request, without the desktop defaults/notification fallback. Stopped JSON status is `{"running":false}`. Live status keeps the correlated runtime envelope; held or unreachable authorities fail. The obsolete desktop status formatter is removed. The broader legacy runtime route remains for commands not yet migrated.

All 16 runtime-backend tests pass, covering argument bounds, real process forwarding/failure/timeout, insecure/symlink executable rejection, status correlation, owner distinctions, and prior input/pairing safeguards. The CLI scheme and aliases build. The required stack script passes all 39 constrained-thread tests, both native builds, and unchanged static budgets. Source hashes and the isolated native base are recorded in `verification.json`; concurrent unrelated WoW/Android/desktop work is excluded.

`scripts/verify-headless-lifecycle-cli.py` passes against the actual native CLI, Rust receiver, and Rust bridge. Its private workspace HOME disables input and Bonjour, uses an ephemeral port, enables configuration writes explicitly, and is deleted after receiver cleanup. It verifies stopped status without initialization, invalid arguments without writes, start/status, pairing code/payload, duplicate-start rejection, restart with preserved options/identity/state bytes, stop, idempotent stop, held-authority rejection, and a corrupt legacy-profile startup that retains the original plist and writes no replacement state. The prior four-output/one-rejection pairing test-bridge check also passes against this CLI. No real phone pairing, physical input, live user profile conversion, or signing acceptance is claimed.

Setup and agent instructions now describe headless lifecycle and previews. Accessibility still uses the direct host CLI; its native wrapper, pairing cancellation, remaining GUI-dependent operations, complete migration, GUI deletion, and tools-only installation/release acceptance remain outstanding. CLI lifecycle is still explicitly host-CLI-only in the MCP capability ledger; the ledger's successful verification does not claim an MCP lifecycle tool exists.
