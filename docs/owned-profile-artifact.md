# Owned portable artifact v1

The pure Rust `OwnedProfileArtifact` codec packages version-5 configurations with profile-owned appearance, editable geometry/input, all eight paint states and validated image-resource tables. It is a separate container from the existing version-4 portable artifact. Existing explicit owned authorities now use it through native CLI profile import/export and MCP `import_profiles`/`export_profiles`. Phone format negotiation and automatic migration remain gated.

The JSON envelope has exactly five fields: `schema` (`com.codybontecou.thumble.owned-profile-artifact`), `artifactVersion` (1), `catalogRevision` (the current controller-template/device-frame/generation revisions), `contentHash`, and `document` (an embedded version-5 configuration object). Unknown envelope fields, duplicate keys at any depth, unsupported catalogs/versions, invalid documents and oversized inputs fail before returning a document.

`contentHash.algorithm` is `sha256`; `canonicalization` is `exact-json-utf8`. Its lowercase hex value hashes the exact UTF-8 bytes of the embedded `document` value, from its opening `{` through its closing `}`. Whitespace inside that value counts. Whitespace outside it does not. This avoids RFC 8785's conversion of numbers to IEEE-754: unknown large integers and precise decimal spellings survive without rounding. This checksum detects changed content; it supplies no sender authentication. Consumers must validate the envelope, digest, full configuration and portability before using the document.

Export accepts all profiles or one case-insensitively selected UUID. It preserves raw nested profile/binding/extension values and never modifies the source. The export timestamp is supplied explicitly. A single selection becomes active; it remains default only if it was the source default. Its binding maps are scoped to that profile, and active aliases follow the selected map or the original active aliases when no explicit map exists. Export validates all source profiles and binding/extension content before selection, so selection cannot hide nonportable data.

Canonical profile `launchTarget` is intentionally omitted. Aliases are rejected by the version-5 document codec. The existing recursive portable-field policy rejects credentials, authority/device identity, local paths, launch metadata and arbitrary embedded binary payloads, including normalized spellings. Unknown safe metadata is retained. The two exceptions are `data` containing exactly a validated `resourceSHA256` reference within a profile, and that profile's canonical `appearanceResources` table. The version-5 document validator checks exact Base64, digest keys, every reference and cumulative resource size. Unknown metadata cannot masquerade as a resource table, including through JSON Pointer characters in its property names.

The complete encoded container is bounded to 8 MiB, including its metadata. Ordinary strings are limited to 256 KiB, keys to 256 bytes, containers to 4,096 entries and traversal to 64 levels. Validated resource tables use the existing document/resource byte budget. The frozen fixture is under `Host/fixtures/owned-profile-artifact/v1`; its test regenerates the result through the public pure codec and compares exact bytes. Existing v4 codecs and peer advertisements remain unchanged.

CLI/MCP import uses exact configuration revisions and deterministic invocation/draft/commit identities. Retries reuse prepared drafts and committed results; different content/options under the same invocation are refused. Replacement first matches UUID, then an unclaimed case-insensitive name, retaining the destination UUID and local launch association. Append-as-copies derives new profile UUIDs from the invocation and gives conflicting names numeric suffixes. Selected/default profile references and binding-map keys follow the resulting identity map. Native response validation accepts the exact-byte hash encoding only for portable artifacts; generation results retain their existing RFC 8785 contract.

Safe root extensions merge by exact field name, with incoming values replacing matches and other destination values retained. The raw `ownedConfigurationExtensions` state sidecar preserves those values across draft edits, commits, restarts and later exports. Envelope/known-field collisions are refused when rebuilding the owned document. Authority credentials and other state fields remain outside that sidecar. A candidate is validated against authority/credential constraints before a draft is saved.

Owned imports require an existing schema-4 authority and a valid owned artifact. A version-4 artifact is not silently converted, and a valid version-5 artifact cannot initialize a fresh legacy authority or trigger migration. Legacy authorities keep their existing version-4 codec. MCP import additionally requires its existing configuration-write gate and the receiver's write authorization; export is read-only.

Remaining integration: explicit legacy conversion, retained phone reconciliation and transfer format 5, file-backed artwork tools and automatic migration activation. These remain required before removing the remaining skin runtime and desktop UI.
