# Local customization reset

`thumble customization reset [--profile PROFILE] [--variant landscape] --invocation-id UUID` now uses a typed local authority transaction rather than desktop preferences. Active/default/name/UUID selectors use the authority catalog. Owned profiles accept the canonical primary/landscape canvas; portrait requests fail without changing authority. Legacy profiles retain the existing native orientation behavior.

An owned reset installs the native default customization and, when a bank already exists, replaces all eight saved appearances with that default. The existing `profile reset` command uses the same owned reset preparation. A field present only in a dark/held-trigger state must not reappear after reset. Reset is an intentional replacement of the selected customization, including its controls, geometry, paint, styles, assets and local feedback choices; it retains the profile identity, name, output mode, active/default selection, unrelated profiles and metadata outside that scope. Opaque data that the lossless merge cannot safely replace causes refusal rather than silent deletion.

The native operation handles the selected profile directly, avoiding temporary legacy orientation mirrors. Identical resets return a no-op even at a later clock time. The authority independently checks that every saved state matches canonical reset paint, including the case where a helper returned an unchanged bank. Only redundant default control-bar records are ignored in that comparison.

The normal raw draft, revision/CAS, input-release barrier, atomic persistence and durable receipt path owns the write. Exact committed retries work with the native helper unavailable. Local MCP already exposes `customization.reset` and `profile.reset` through the private configuration-draft operations; configuration-write opt-in and exact draft/authority revisions remain required. No migration or public phone-format activation is introduced.

Frozen plain/banked responses for both commands are in `Host/fixtures/customization-reset/v1`. Native tests cover state-only paint, unrelated profiles, later-clock no-ops and frozen responses. Rust tests merge the correlated native views into exact source bytes and reject forged leftover paint in one or all states. The full transform also runs on a constrained 512 KiB thread.
