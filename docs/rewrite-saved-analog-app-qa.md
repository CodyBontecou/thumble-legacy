# Saved analog app acceptance

The separate `analog` app fixture uses the real saved authority, native role 6 input, role 7 catalog pin and role 8 delivered map. Neither app test supplies a map or calls engine touch methods. The selected profile contains left/right standard sticks, a vertical left trigger, a horizontal right trigger and South. The `analog-unsupported` fixture rotates a retained pad and must reject admission before any map or input is installed.

Android injects five touchscreen pointers through instrumentation's OS input interface. The iOS UI-test runner uses a small, fixed XCTest event record: five control pointers, button pointer release, then a Done press while the other four captures remain held. At most five pointers are active together. The helper belongs only to the UI-test target, has fixed timing and bounded coordinates, and cannot be called from JS or the shipped app. It uses private XCTest interfaces and fails explicitly if the installed Xcode runtime does not support them. This is a test tooling restriction, not an application entitlement or security bypass. [Appium's input-event documentation](https://github.com/appium/appium-xcuitest-driver/blob/master/docs/guides/input-events.md) describes this XCTest mechanism.

The native recording backend admits one simultaneous report with South, LX near 0.4, RY near -0.4 and both triggers near 0.4. Other report fields must be exactly neutral. This app-only oracle permits ±0.025 on those four intended components for screen-coordinate rounding, then pins the exact admitted bytes throughout a hold of at least 1.5 seconds, with zero neutral pulses and the unchanged 350 ms input TTL. The existing direct SDK fixture modes retain their exact byte golden.

The bound assumes the QA display has at least one physical pixel per logical point and the connected viewport is at least 240 points high. A half-point coordinate error on a trigger of height `0.11 × 240`, transformed through its 0.03 deadzone, plus half an 8-bit report step is below 0.0215. The analogous standard-stick bound with diameter `0.3 × 240` and 0.12 deadzone is below 0.0159. The chosen 0.025 bound covers both; it does not permit combining values from different reports. Pre-quantized perpendicular stick values may differ from zero by less than half a report LSB; the backend still requires their encoded fields to be zero.

Done must return to Home and produce the native released/neutral acknowledgment. Tests separately verify real native-to-JS saved-profile summary and semantic L/R/LT/RT/A labels. Raw typing logs, XML and xcresult attachments stay in private runner temporary storage because they can contain the synthetic invitation. CI publishes only strict one-case, zero-skip fixed outcome JSON. Legacy UIKit five-case/75-second, Android ten-case, and saved-button corner/unsupported gates remain independent.

These are headless simulator acceptance witnesses. Physical touch feel, haptic behavior, visual review, actual game behavior, and the separately observed hosted iOS long-hold TLS read deadline remain open.

Current evidence: Android supported and unsupported modes pass strict one-case checks. The iOS five-pointer case is experimental and has not passed; native saved-map admission and first-neutral sample did pass in a diagnostic run. Do not treat the experimental iOS workflow additions as acceptance evidence.
