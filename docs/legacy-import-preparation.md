# Explicit legacy import preparation

Use `thumble-host configuration prepare-import --source-file /absolute/setup.json` or MCP `prepare_legacy_profile_import` with `sourceJson` to prepare a version-4 local configuration/export for an owned authority. The result contains `artifactJSON`, its checksum, the exact original `sourceSHA256`, and per-profile layout/recovery reviews. Preparation is read-only and works without a running receiver or desktop GUI. It does not initialize authority state, pair phones, install packages, change format offers, or activate migration.

For a referenced skin, supply the original archive explicitly: CLI `--package PROFILE_UUID=/absolute/original.pocketpad`, or MCP `packages: [{profileId, archivePath}]`. UUIDs must be unique and belong to referenced source profiles. Missing packages, mismatched/invalid archives, unsupported layouts, unsafe files and failed materialization return no partial artifact. Package lookup does not depend on an installed library or hosted service. Inputs stay in place; source/package checksums identify the bytes consumed by native preparation.

The source may be a local version-4 configuration with inline artwork or a valid hashed version-4 portable export. Hashed exports are validated before their wrapper is adapted. Source profiles and future metadata enter the existing lossless migration merger as exact JSON values. The new explicit portable mode materializes all eight light/dark and held-trigger states even for profiles with no skin, then pools binary data into validated resource tables. The old native migration mode and its five frozen responses remain unchanged. Portrait-only sources use the existing deterministic landscape arrangement and retain their review reasons; conversion does not grant human approval.

The owned artifact includes a `legacyConversion` root report with the original source checksum and profile reviews. Existing source metadata with that name is refused rather than overwritten. Local launch associations are excluded from the portable copy; importing into an existing profile retains its destination launch association. Other nonportable metadata is refused. A control-bar paint owner called `launch_target` is accepted only at its exact validated appearance-bank location; local launch fields elsewhere remain forbidden.

After reviewing the result, import its `artifactJSON` through the existing revision-checked owned CLI/MCP transaction. Preparation itself never commits. Owned import still requires an existing explicit schema-4 authority. Automatic authority migration and paired format-5 transfer remain gated on retained phone reconciliation and the remaining acceptance checks.

Source JSON is limited to 8 MiB, each original package to 40 MiB, mappings to 256 profiles, and the final owned artifact to 8 MiB. Files must be absolute paths to current-user-owned regular files; final symlinks, special files, size overflow and changes during the bounded read are rejected. The native helper retains its existing request/output/deadline limits. Local MCP allows larger frames only for its bounded source-update/import/preparation tools, retaining the 256 KiB ordinary-request limit and 24 MiB absolute frame ceiling.

The process verifier checks five native migration cases plus a standard hashed export, preservation of original files, no implicit authority initialization, preparation with configuration writes disabled, large MCP preparation/import, retry without duplicate persistence, and export of retained conversion metadata. The portable mode also runs on the existing 512 KiB constrained thread without increasing inline or frame budgets.

For a whole receiver authority rather than a portable file, the separate explicit offline [authority migration](authority-migration.md) path now plans/applies the existing backed-up transaction. It preserves local launch metadata and trust instead of exporting/importing the receiver state. It does not remove the retained-phone admission or automatic startup gates described above.
