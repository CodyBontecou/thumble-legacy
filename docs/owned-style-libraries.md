# Local style-library interchange

`thumble style import FILE [--merge] --profile ID --invocation-id UUID` and `thumble style export --profile ID -o FILE` use revision-checked local authority transactions and inspection. They do not read desktop preferences or require the desktop GUI. The dedicated local MCP tools are `import_style_library` and `export_style_library`; import requires configuration-write opt-in, an expected configuration revision and a stable invocation UUID. MCP accepts JSON content rather than a host path.

Imports accept the existing `{ "styles": [...] }` JSON and the pooled file emitted by export. The pooled schema is `com.codybontecou.thumble.style-library`, version 1, with `styles`, `appearanceResourceVersion: 1` and a SHA-256-keyed `appearanceResources` table. Embedded images occur once even when many styles reference the same bytes. Files are limited to 8 MiB; existing per-image and complete-authority budgets still apply. Native CLI file reads reject symlinks and nonregular descriptors, including FIFOs.

Merge replaces tokens with matching IDs and retains unmentioned tokens independently in every saved appearance state. Replace installs the imported catalog in every state. Both refuse orphaned style references and missing destination asset references. An asset-backed icon requires its ordinary profile asset to exist in the destination; use full profile interchange when transferring a complete design. Embedded fill/image bytes travel in the style file.

The decoder rejects duplicate JSON keys, unsupported schemas, corrupt resource digests, duplicate/invalid token IDs and non-null fields that typed normalization would discard. It does not silently drop future input fields. Existing opaque token metadata and precise numeric spellings survive merges by identity. Unknown data on a removed token remains subject to the lossless-merge refusal rather than being silently deleted.

For an explicit owned authority, a changed import into an unbanked profile first prepares eight equivalent appearance states. Existing banked profiles retain their distinct state catalogs in merge mode. Only style catalogs, required pooled resources and the selected profile timestamp are patched. Geometry, outputs, groups, control identities, saved control haptics and unrelated profiles remain owned by their original data. Imported reusable styles can themselves contain haptic settings; saved control settings are not rewritten by importing a catalog.

The normal raw draft, input-release, revision/CAS, atomic persistence and durable replay path owns writes. Identical imports do not advance the configuration revision; committed retries work with the native transformer unavailable. Changed content under the same invocation ID and stale revisions fail. Resource blobs are retained when removing tokens so future or opaque references are not discarded; ordinary portable profile export can prune known unused resources. Retained resource growth can reach the authority bound and fail safely.

Legacy authorities use the same typed import path while preserving the legacy format; import does not activate migration or shipping phone format 5. This closes style-file ownership through CLI/MCP, but does not retire the remaining package runtime, portrait mode or desktop targets.

Run `scripts/verify-style-library-authority.py --help` for the actual-process verification inputs. Frozen native requests/responses are in `Host/fixtures/style-library/v1`; validation logs and artifact hashes are recorded in [the evidence](feature-removal-evidence/style-libraries/README.md).
