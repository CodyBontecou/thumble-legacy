# Owned design workspaces

Explicit owned authorities support the existing local `design begin`, `update`, `review`, `inspect`, `critique` and `apply` commands and matching MCP tools. A native capture uses the bounded resource-aware reader and can target the authority or an exact private-draft revision. It does not decode a format-5 profile as a legacy stored profile or replace authority bytes with a display projection.

Owned sessions carry an `ownedAuthority` marker, capture a single landscape canvas and reject portrait layout edits. Their source remains editable CSS/artwork plus a frozen native artboard, profile and binding contract. Layout edits still require exact native control identities and are bound to the original and reviewed profile hashes. The owned-authority marker is bound into review evidence; changing it after review fails before package-library access. Review files, sources, renderer identity and configuration/draft revisions retain the existing stale-evidence checks.

An owned review renders light/dark × Base/LT/RT/LT+RT, including normal, pressed, active, disabled and mixed control states. Frame titles identify the action set. Saved/reviewed native PNG comparisons permit at most one 8-bit RGB level for codec-round-trip antialiasing; dimensions, geometry, outputs and saved haptic fields remain exact. Optional bar and drawer evidence uses the same state-specific appearance. Structural and quality diagnostics still block apply; this change does not authorize publication or human approval.

Applying an owned design sends the bounded reviewed compiler artifact to the retained native helper without installing it into a skin library. The helper validates artifact hashes, the frozen target and any typed layout plan, materializes eight ordinary appearance snapshots, and pools their resources through the normal owned codec. No skin reference, baseline or orientation variant is attached to the profile. The CSS compiler and archive format remain private intermediate machinery pending general design-module extraction; their existence does not mean skin runtime retirement is complete.

Visual replacement preserves explicit per-control feedback settings, including style, pattern, intensity, sharpness and duration. Feedback is restored in the element/mirror collections and the bar/reveal controls before normalization. Haptic configuration remains independently editable through the ordinary control operations. The authority independently verifies nonvisual declarations and saved haptic fields across all eight resolved states, alongside geometry, output, sidecar and unrelated-profile checks.

The existing raw projection merge, durable private draft, input release, revision/CAS, atomic save and commit-receipt path owns the write. Unknown source metadata is retained; a projection change that would erase opaque data fails rather than overwriting it. Retrying committed apply after receiver restart returns the original receipt. Legacy sessions keep their guarded legacy installation path until migration; an old workspace whose authority changed must be recaptured.

Regression fixtures live in `Host/fixtures/owned-design/v1`. Existing projection/native-operation oracle bytes remain unchanged; only their test-source provenance hashes advance after adding the new cases. Evidence is in [the design workspace verification](feature-removal-evidence/owned-design/README.md).

This is an explicit owned-authority path. Automatic migration, shipping phone format activation, remaining file-backed editing, active skin/portrait UI deletion and desktop release retirement remain outstanding. Native test/build evidence does not establish physical haptics, network latency or live WoW behavior.
